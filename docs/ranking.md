# エンドレスのランキングと挑戦状（2026-11-23 時点）

## エンドレスの今の設計
- **入り方**：ノルマを7回払うとクリア画面。「エンドレスへ」で続け、「ここで終える」で結果画面へ。
- **終わり方**：ノルマを払えなかったら終わり（クリア済みなので結果は「エンドレス終了」）。
- **ノルマの額**：8週目は表の最後（ふつう290）。そこから**毎週×1.5**（`CONFIG.taxGrowth`）。難しさの倍率もそのまま掛かる。
  - ふつう：8週目290 → 435 → 653 → 980 → 1470（12週目）
  - 難しい5〜9：8週目435 → 653 → 980 → 1470 → 2205
- **お邪魔**：ノルマを払うたびに3枚（表の最後の行のまま）。
- **市**：払った回数が増えるほどレアが混ざりやすい（8%＋回数×4%）。
- **殿様モード**：段2・3は、8週目より先も毎週ノルマの条件が付く。
- **難しさの決まり**（傷む・混ぜた列・維持費・持ち越し上限など）は、エンドレスでもそのまま。
- **ごほうび**：豊穣ポイント（日数・払った回数に比例）。評価の点は結果画面だけ。
- **記録**：エンドレスの自己ベスト（難しさごと）。シェアのカードと挑戦状は「クリア・◯日目」を出す。
- **遊ばれ方**（公開版の記録）：クリア後に続けたのは5回、49日目から1〜5週（最長84日目）。ノルマが毎週1.5倍なので、稼ぎの伸びが雪だるま式の人（苺と巣箱）ほど長く続く。

## 今あるもの（サーバーなしで動く）
- **種**：プレイごとに出目の流れを決める数（`state.seed`）。乱数の位置（`state.rngState`）も保存するので、続きから遊んでも同じ流れが続く（`src/game.ts` の `nextRand`）。演出の見た目の乱数（回っている間の絵柄・カットイン）は `Math.random` で、出目の流れには触らない。
- **挑戦状リンク**（`src/ui/challenge.ts`）：URL の `?c=` に「種・難しさ・殿様の段・農家・送った人の結果」を入れる。開くとタイトルに挑戦状のカードが出て、「受けて立つ」で同じ種・難しさ・農家で始まる（解放していない難しさ・農家でも遊べる。腕前と解放の品は受け取った人のもの）。結果画面に相手との比べ（クリアしたか → 日数 → 稼いだ合計）。シェアの文の URL も挑戦状のリンク。
  - 同じ種でも、選んだ操作が違えばそこから先の出目は変わる（最初の袋・最初の出目は同じ）。
  - 挑戦状のプレイはチュートリアルを出さない（決まった出目に差し替えると相手と同じにならない）。
- **エンドレスの自己ベスト**：クリアしたプレイが何日目まで行ったか、難しさごと（殿様は段ごと）に `meta.endlessBest` へ。記録の画面に出す。
- **送る形**（`src/ranking.ts`）：`rankingEntry`（板・週・種・日数・稼ぎ・評価・版）。`RANKING_URL`（`src/config.ts`）が空の間は何も送らない。
- **週替わりの種**：`weeklySeed()`（日本時間の月曜はじまり。週の名前 2026-W48 など）。
- **記録（テレメトリ）**：まとめに `seed` と `challenge`（挑戦状のプレイか）を足した。

## これから決めること
1. **比べるもの**：エンドレスの日数（同じなら稼ぎ）／週替わりチャレンジ／評価の点
2. **置き場所**：Cloudflare Workers ＋ D1（おすすめ）／今の Apps Script
3. **週替わりチャレンジの準備**：全員同じ（解放の品・腕前なし）にする。今の挑戦状は受け取った人の解放の品を使う
4. **名前**：ログインなし・ニックネームだけ。ひどい名前ははじく
5. **ずるの防ぎ方**：まずは確かめずに始め、人が増えたら「種＋操作の記録」を送ってサーバーで遊び直して確かめる（ゲームの中身は同じ種・同じ操作で同じ結果になる）

## サーバーの口（作るとき）
- `POST {RANKING_URL}/submit`：`RankingEntry` ＋ `name`
- `GET {RANKING_URL}/top?board=d9&week=2026-W48`：上位（name・day・earned）
